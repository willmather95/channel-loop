channel-loop: how one tick flows

TRUTH in, one guarded change out, measured later, beliefs updated. Every change to the right of the agent goes through another repo's limits.
TRUTH

DuckDB warehouse

ads_daily, ads_settings_daily, web_daily, loop_decisions. ads-guardrail and marketing-warehouse schema.

AGENT

Observe + hypothesize

Marginal return, pacing, CTR decay, site signups. One concrete change per kind, with a $/day estimate.

AGENT

Choose (Bayesian)

Per kind: effect = w0 + w1 x estimate. Act on the best posterior mean above the bar, or hold.

AGENT

Measure + update

Diff-in-diff vs untouched campaigns, or the A/B control arm. Each result updates one posterior.

HANDS

HOME

Daily tick: cron, GitHub Actions or serve

Idempotent: a finished tick is a no-op, a crashed tick resumes at its first unfinished step. One runner at a time (flock).

MEMORY

The loop's only state. replay re-derives every decision, score and belief from it.
